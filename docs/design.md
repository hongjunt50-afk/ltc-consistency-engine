# 设计与边界（v0.1，2026-10-28）

## 一句话

不做"又一个长护险管理系统"，只做**服务过程一致性核验引擎**：机构提交的服务记录、护理计划、人员资质之间是否自洽，不自洽的地方在哪、依据哪份文书。

## 为什么要收窄

立项时的原始描述是"失能等级评估辅助、服务派单、上门服务过程记录质控、异常识别"四件事。开工前做 GitHub 竞品核查后砍掉一半：

- **失能等级评估已饱和**：`zzx749/shineng`（2026-10）已完整实现 GB/T 42195-2022 的 26 个二级指标、五档等级阈值、自动判定与人工纠正留痕、PDF 报告，另有 6 个以上同类项目。再做是重复劳动。
- **派单/排班是通用调度问题**，无政策约束，谁做都一样，没有差异化空间。
- **服务过程质控/稽核**：GitHub 搜「长护险 监管」「护理 质控 稽核」「医保 智能监管 反欺诈」「long-term care fraud detection」全部 0 结果，是真空。

## 为什么规则可信

不自编规则。全部来自：

1. 《长期护理保险服务管理文书（2026 年版）》，国家医保局办公室印发
2. 《国家长期护理保险服务项目目录（试行）》，医保发〔2025〕24 号

抽取脚本 `tools/extract_ruleset.py` 从官方 PDF 抽结构化数据，并在抽取过程中做四类自校验，任一失败则不产出文件：

- **数量**：36 项 = 生活照护 20 + 医疗护理 16
- **序号连续性**：1..20 与 1..16 不许断号
- **三处副本逐字一致**：36 项在"护理服务建议表"、"护理服务计划表"、"月度汇总表"三处重复出现，排版不同（`1.` / `□1.` / 数字独占行），三种解析路径得到的名称必须完全相同
- **分区求和**：巡查记录表 8 个分区的声明分值必须相加为 100，且分区内各检查项分值累加必须等于该分区声明总分

抽出来的巡查项分值最初靠二手报道记录成"六分区 82 分"，PDF 原文核对后发现漏了"违法违规行为查处 8 分"和"综合评价 10 分"两个分区——真实是 8 个分区 30 项。这正是要求从原文核对的意义。

## 三类结论分级

- **E（硬违规）**：字段间存在明确矛盾，或直接违反准入/签字/资质要求。对应巡查表扣分项与质量评价表的"直接判不合格"情形。
- **W（需复核）**：可能是正常业务波动，需要人看。例如服务项目不在计划内（可能临时加项并已书面同意）、月度频次低于计划（可能计划刚调整）。
- **I（数据质量）**：填报口径错误，不涉及合规判断。

分级的目的是**只把 E 推给人看，W 批量抽检**——机构最怕的是"每条都报警"，那样等于不报。

## 假阳性是一等公民

`tests/fixtures/clean_case.json` 是三条完全合规的记录，测试断言 `findings == []`。任何一条规则写歪导致误报，这个测试立刻红。规则引擎的价值不在于报得多，而在于报出来的都经得起机构反问。

## 为什么不用 LLM 做主线

一期刻意留在规则层，理由：

- 判据是政策原文的字段约束，规则能做到 100% 可复现、可审计；LLM 做不到，而稽核结论需要能上法庭/进报告。
- 每条结论必须能指向文书条款。规则引擎天然带 `clause` 字段，LLM 生成的解释会给不出精确出处。
- LLM 的合理位置是二期：服务记录的文字描述与照片是否匹配、异常说明是否敷衍、护理建议与失能等级是否合理——这些需要语义理解而非字段比对。

## 不做的事

- 不做失能等级评估，不输出任何等级判定结论（不出现"辅助诊断""疾病评估"一类措辞，不触碰医疗器械监管边界）
- 不做排班派单
- 不接入任何真实患者数据；仓库内两份用例全部虚构

## Excel 适配器的取舍

机构交来的不是干净 JSON，是自己多年攒下的 Excel。适配器的全部复杂度都花在"尽量不让人改表"上：

- **别名表而非固定表头**：每个字段维护一组常见写法（`参保人姓名` / `姓名` / `老人姓名` / `服务对象姓名`），别名按「具体→通用」排列，先命中者胜。这样既有「参保人姓名」又有「护理人员姓名」的表不会互相抢列，只有一列「姓名」的表也能落到参保人。
- **表名按最长别名判定**：服务记录表常叫「参保人服务记录」，如果按字典序遍历会让「参保人」抢走。改成比长度 + 显式优先级（records > plan > caregivers > elders），因为记录表的名字最容易带别人的名字。
- **表头位置不固定**：前 10 行里找匹配字段最多的一行。机构表第一行通常是大标题「某某区参保人台账」。
- **能报就报，不静默丢**：参会对不上、人员不在名录、表头缺列，一律带工作表名 + 行号 + 字段名报出来。跳过的行更要报，因为静默跳过会让机构以为数据进去了。
- **未知人员补录而非跳过**：服务记录里出现的人员若不在人员表，补一条资质为空的人员。这样资质校验会自然报硬违规；如果直接跳过，等于把最该查的问题藏起来了。
- **身份证精度丢失要提示**：18 位数字在 Excel 里被存成浮点会丢末位。检测到 `float >= 1e15` 就报 W 提示改文本格式。这是真实高频事故，不是理论风险。
- **项目数合计自动补**：没填就按实际列出的项数补，否则整表每行都报数据质量，告警疲劳。

阈值与别名都在模块顶部常量里，改地区口径只改表不改逻辑。
